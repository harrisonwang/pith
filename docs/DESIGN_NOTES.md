# 设计说明

spoor 把文档转成便于程序和模型读取的文本；如果检测到有些内容可能没读出来，就会给出警告，并在支持的格式中记录页码和坐标。

## 结构

```text
文件 / URL / stdin
        ↓
CLI、Python、Node.js、WASM
        ↓ 文件内容、名称和可选参数
spoor-core
  识别格式 → 检查大小和结构 → 读取内容 → 返回文字、表格和警告
        ↓
ParseResult / SpoorError
```

`spoor-core` 不读文件、不联网、不读取环境变量，也不启动其他程序。CLI 和各语言包负责读取文件，再把内容交给 `spoor-core`。因此，命令行、桌面应用、浏览器和 Cloudflare Worker 可以共用同一套解析代码。

## 为什么这样设计

1. **文档返回 Markdown，表格返回 JSON。** 应用可以通过 `content.kind` 判断结果类型。
2. **成功不代表内容完整。** 完全无法读取时会报错；能读出一部分但可能有遗漏时会给出警告。检测到扫描页时，spoor 会留下警告。
3. **可以只读一部分。** 指定页、工作表、行或列，可以减少耗时、内存占用和模型输入长度。
4. **同样的输入得到同样的结果。** `spoor-core` 不调用模型、不做 OCR，也不联网。同一版本使用相同文件和参数时，结果应保持一致。
5. **详细位置需要单独开启。** PDF Markdown 默认带有页标题；另外返回页码、幻灯片编号和 PDF 近似坐标会增加数据量，需要时可将 `provenance` 设为 `page` 或 `block`。

## CLI 和各语言包保持一致

CLI 和各语言包都使用以下数据：

- `ParseRequest`：文件内容、文件名、格式提示、筛选参数和大小限制。
- `ParseResult`：文档或表格、警告、统计信息，以及需要时返回的页码和坐标。
- `SpoorError`：固定错误码、错误原因、处理建议、能否恢复，以及出错环节。
- `spoor://`：指向 spoor 已检查过的图片或嵌入文件，不是普通文件路径。

不同语言可以采用各自的命名方式和字符串下标单位，但错误码、警告码、页码与行列号的计算方式，以及默认限制都必须一致。

## 文档与表格为什么分开

正文适合用 Markdown 表示，可以保留标题、段落、列表和分页。大型表格转成 Markdown 后会很长，也不容易看出实际读了哪些行。因此，表格默认返回 JSON，并注明表头、工作表、行号和是否截断。

需要记录 CSV 或 XLSX 的单元格位置时，可以改用 Markdown；其他情况更适合使用表格结果。

## 处理不可信文件

`spoor-core` 的大小限制和 ZIP 检查能提前拒绝一部分异常文件，但不能强制终止超时任务，也不能隔离内存耗尽或底层库崩溃。处理公开上传时，仍应把解析放进独立进程、容器，或严格限制内存和执行时间的 WASM 环境。

详细要求见[安全说明](../SECURITY.md)。

## spoor 不做这些事情

- OCR 和视觉模型
- RAG 的分段、向量化、检索和排序
- 调用大模型，或判断某段文字是否足以支持结论
- 文档编辑、版式还原和通用 Office 自动化
- 云端存储、账号、计费和自动化流程

这些事情可以由其他工具和 spoor 配合完成，但 spoor 本身不提供。
